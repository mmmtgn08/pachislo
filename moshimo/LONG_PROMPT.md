# 週1回の長尺動画 定期タスクのプロンプト

Claude Code の定期タスク（毎週日曜）に、以下の文面を登録しています。
内容を変えたいときはこのファイルを編集し、Claude に「長尺の定期タスクのプロンプトを更新して」と頼んでください。

---

【週1回の定期タスク】「もしも」長尺動画（8〜11分・横長）を1本作り、投稿ワークフローを起動してください。チャットでの確認は不要です。返事は日本語で。

1. GitHub リポジトリ mmmtgn08/pachislo の main ブランチから、GitHub MCP の get_file_contents で次を読む:
   - moshimo/GUIDE_LONG.md（長尺の決まり。必ず従う）
   - moshimo/GUIDE.md（事実のルール・使えるシーン・映像と話の一致。必ず従う）
   - moshimo/history.jsonl（過去の投稿。format が long の回と同じテーマは使わない）
   - moshimo/STATS.md（あれば。再生の多かった方向をテーマ選びの参考にする）
   - moshimo/topics/long_sample.json（形式の見本）
2. ガイドに沿って、今日（日本時間）の日付を date に入れた長尺の台本JSONを1本作る。
   - 事実のルールを最優先する。少しでも怪しい数字・主張は使わない。数字は「計算では」「目安で」を添える
   - 全章の text の合計を 3,200〜4,000 文字にする（書き終えたら数えて確かめる）。章は4〜6個
   - 各章に「なぜそうなるのか」の解説を2〜3場面入れる。ショートの台本をそのまま並べない
   - 各場面のナレーションの主語が、画面に映る type を選ぶ。type と event の組み合わせを1つの章の中で繰り返さない
3. GitHub MCP の actions_run_trigger で moshimo.yml を ref main、inputs {"script_json": "<台本JSONを1行の文字列にしたもの>"} で起動する。
4. 描画に1時間前後かかる。75分後と、まだ終わっていなければ105分後に actions_list で結果を確認する。台本の検証エラーなら直して1回だけ再実行。それ以外の失敗は原因を短くまとめる。
5. git の push やファイル編集は行わない（記録はワークフローが行う）。
6. 最後に「テーマ・章の一覧・動画の長さ・動画URL（history.jsonl にあれば）・サムネイルが設定できたか（ワークフローの警告を見る）」を短く報告する。
